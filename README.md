# RealtimeIntensity v1.4.0

Androidスマートフォンの内蔵加速度センサーを使って、地震動をリアルタイムに処理し、
「リアルタイム震度相当値」や加速度を表示する学習・検証用アプリです。

スマートフォンを簡易的な震度計として扱うことを目的としていますが、
**気象庁の正式な震度計・震度観測装置ではありません。**
表示値は参考値であり、気象庁が発表する震度と一致することを保証しません。

アルゴリズムの出典、係数、近似・簡略化した点については
[`ALGORITHM.md`](./ALGORITHM.md) を参照してください。

## v1.4.0 時点の概要

現在のRealtimeIntensityは、単なるリアルタイム表示だけでなく、
気象庁の3成分CSVを用いたオフライン検証と、計測データのCSV書き出しまでを含む
検証用ツールとして構成されています。

主な機能は次のとおりです。

- Android加速度センサーからX/Y/Zの3軸加速度を取得
- 防災科研方式（2008年版係数）をもとにした6段biquad IIRフィルタによるリアルタイム震度相当値の算出
- 3軸合成加速度からのリアルタイム震度相当値表示
- リアルタイム加速度、震度階級、PGA相当の色バー、震度履歴、XYZ加速度波形の表示
- センサーの静止時オフセット・ノイズの常時モニタ
- 測定データを気象庁3成分CSVと同じ基本構造で保存
- 保存したCSVをAndroidのStorage Access Frameworkから任意の場所へ書き出し
- 気象庁形式または本アプリ書き出し形式の3成分CSVを1ファイル読み込み、オフライン検証
- オフライン検証で、FFTベースの計測震度と、本アプリの漸化式リアルタイム処理を比較

## リアルタイム表示

メイン画面は、表示内容をまとめた2列のモニターカードを中心に構成しています。

左上は「震度階級」と震度アイコン、右上は震度履歴帯です。
左下は「リアルタイム震度」と「リアルタイム加速度」、それぞれの色バーです。
右下はXYZ加速度波形です。

現在の主要な表示設定は次のとおりです。

- 画面全体の背景: `#000049`
- メインカード: `#283C64`
- 詳細カード: `#1B2D4D`
- 「震度階級:」: 20sp
- 震度アイコン: 80dp × 50dp、文字32sp、文字は中央揃え
- 「リアルタイム震度:」「リアルタイム加速度:」: 13sp
- リアルタイム震度・リアルタイム加速度の数値: 22sp
- XYZ加速度波形: 80dp
- 震度履歴帯: 100コマ、約10秒分
- フォント: `GenZenGothicKaiC`
- UIはAndroidX/Material Componentsをベースに、Material 3 Expressiveを意識した大きな角丸・カード・ボタン構成

### 表示更新頻度

センサー処理とUI表示は分離しています。

- センサー取得・フィルタ・震度計算: センサーイベントごと
- CSV保存: 本番サンプルを毎サンプル記録。UIの間引きとは独立
- リアルタイム震度の数値: 約30Hz
- リアルタイム加速度の数値: 約30Hz
- XYZ加速度波形: 最大10Hz
- 震度階級バッジ・色バー: 約1Hz
- 震度履歴帯: 10Hz

震度階級の判定自体にはヒステリシスを使用していません。
表示のチカチカを抑えるため、震度階級と色バーの更新だけを約1Hzに間引いています。
一方、履歴帯は直近の確定震度階級を10Hzで記録することで、
XYZ加速度波形と同じ時間軸（100コマで約10秒）にしています。

## センサー取得

`Sensor.TYPE_ACCELEROMETER` を使用します。
Android標準のm/s²で取得した値を、アプリ内でgalへ変換します。

サンプリングは `SensorManager.SENSOR_DELAY_FASTEST` を要求します。
Android 12（API 31）以降では `android.permission.HIGH_SAMPLING_RATE_SENSORS` を
Manifestで宣言しています。これはnormal権限で、実行時ダイアログはありません。

高速サンプリングの登録に失敗した場合は `SENSOR_DELAY_GAME` にフォールバックします。
センサーイベント処理は `HandlerThread` 上で行い、メインスレッドを直接ブロックしない構成です。

## 起動時ウォームアップ

計測開始直後は、約1秒間をウォームアップとして使用します。
この間にX/Y/Zの平均値を求め、フィルタをプライミングします。

ウォームアップ中のデータは、本番計測値としてCSVには保存しません。
これは、静止時の重力成分を含む加速度をゼロ状態のIIRフィルタへ突然入力した際に生じる、
起動直後の大きな過渡応答をできるだけ抑えるためです。

## リアルタイム震度の計算

気象庁の計測震度フィルタ

`H(f) = FL(f) ・ FF(f) ・ FH(f)`

を、防災科研方式（功刀・他、2008）に基づく6段の双2次IIRフィルタとゲインで近似しています。

フィルタ後の3軸を合成し、現在サンプルの振幅 `a` を用いて

`I = 2 * log10(a) + 0.94`

からリアルタイム震度相当値を算出します。

本実装は「リアルタイム表示を優先した近似実装」です。
気象庁の正式な震度算出処理そのものを再現したものではありません。
特に、係数は防災科研方式の2008年版を使用しており、現在の防災科研の改良版とは異なります。
詳細な出典・係数・制約については `ALGORITHM.md` を参照してください。

## データ保存

計測中は、本番サンプルを毎サンプルCSVへ追記します。
UIが約30Hz・1Hzへ間引かれていても、CSV保存は間引きません。

アプリ内の保存先は、原則としてAndroidのアプリ専用外部ファイル領域の
`recordings/` です。概念上は次の場所になります。

```text
/storage/emulated/0/Android/data/com.example.rtintensity/files/recordings/
```

端末やOSの事情で外部ファイル領域を取得できない場合は、アプリ内部ストレージへフォールバックします。

ファイル名は次の形式です。

```text
rtintensity_YYYYMMDD_HHMMSS.csv
```

保存ファイルは、気象庁の3成分CSVに合わせた「6行のメタデータ + 3成分データ」という構造です。

```text
SITE CODE= RealtimeIntensity,,
LAT.=  ,,
LON.=  ,,
Sampling Freq= 100Hz,,
UNIT  = gal(cm/s/s),,
INITIAL TIME = 2026 09 27 22 36 20,,
X,Y,Z
-0.017,-0.017,-0.002
...
```

本アプリの書き出しはスマートフォンの実軸をそのまま記録するため、列名は `X,Y,Z` としています。
気象庁データの `NS,EW,UD` も読み込み可能です。

標準CSVに保存するのは生の3軸加速度 `[gal]` です。
フィルタ後波形、リアルタイム震度、PGA表示用の集計値、SensorEventのモノトニック時刻などの
内部処理値は標準CSVには含めません。

計測停止後は「データを書き出す」からStorage Access Frameworkを開き、
ユーザーが保存先とファイル名を選んでCSVをコピーできます。

## オフライン検証

「オフライン検証」から、次のどちらか1つのCSVを選択します。

1. 気象庁の3成分CSV（`NS,EW,UD`）
2. 本アプリが書き出した3成分CSV（`X,Y,Z`）

CSVから次の情報を読み取ります。

- SITE CODE
- LAT.
- LON.
- Sampling Freq
- UNIT
- INITIAL TIME
- 3成分の列名と加速度データ

検証では同じ波形について、2種類の計算を行います。

### 気象庁方式側

3成分それぞれをFFTベースで処理し、3軸合成振幅から区間全体の計測震度を求めます。

### 本アプリ方式側

記録された3成分を、リアルタイム版と同じ漸化式IIRフィルタへ先頭から順番に入力し、
区間中の最大リアルタイム震度相当値を求めます。

両者について、丸め後・丸め前の値と差を表示します。

本アプリの `X,Y,Z` 書き出しデータについては、オンライン計測時に起動時ウォームアップを済ませているため、
オフライン再生時にも先頭約1秒の平均値を用いてフィルタをプライミングし、
起動直後の過渡応答を二重に発生させないようにしています。

同一波形でも、FFT方式とリアルタイム漸化式方式では処理方法が異なるため、
計測震度が一致しない場合があります。これはオフライン検証の主要な比較対象です。

## ビルド方法

Gradle Wrapperを同梱しています。

```bash
git clone <このリポジトリのURL>
cd RealtimeIntensity
./gradlew assembleDebug
```

Windowsでは次を使用します。

```powershell
.\gradlew.bat assembleDebug
```

主要なビルド設定:

- compileSdk: 34
- minSdk: 26
- targetSdk: 34
- Android Gradle Plugin: 8.5.2
- Kotlin: 1.9.24
- Gradle Wrapper: 8.7
- Java/JVM target: 17
- applicationId: `com.example.rtintensity`
- Material Components: `1.12.0`

Gradle JDKは17系を使用してください。非常に新しいJDKでは、プロジェクトのGradle/AGPの組み合わせにより
ビルドできない場合があります。

## 実機での実行

1. Android Studioでプロジェクトを開くか、上記のGradleコマンドでビルドする。
2. USBデバッグを有効にしたAndroid端末へインストールする。
3. スマートフォンを机など安定した場所に置く。
4. 「計測開始」を押して計測する。
5. 終了時に「計測停止」を押す。
6. CSVを取り出す場合は「データを書き出す」を押して保存先を選ぶ。

オフライン検証はメイン画面の「オフライン検証」から起動します。

## 注意事項

- 本アプリは学習・検証目的です。防災・避難行動の判断には使用しないでください。
- スマートフォン内蔵センサーの特性や設置状態によって結果が大きく変わる可能性があります。
- 測定中に端末の向きを変えると、重力成分の再配分を地震動として拾う原因になります。
- リアルタイム震度は現在サンプルの瞬時値を使う近似表示であり、正式な計測震度そのものではありません。
- フィルタ係数は防災科研方式（2008年版）を参考にした独自実装です。防災科研の公式実装そのものではありません。
- 気象庁方式のオフライン比較も、プロジェクト内の実装による再現計算であり、結果を公的な判定値として扱うものではありません。
- CSVには位置情報を設定していないため、緯度経度欄は空欄です。
