# RealtimeIntensity - 簡易リアルタイム震度計(参考値) [Android/Kotlin]

Androidスマートフォン内蔵の加速度センサーを使い、気象庁・防災科研(NIED)方式の
リアルタイム震度算出処理をできるだけ忠実に再現することを目指した、
学習・検証目的のAndroidアプリです。

**このアプリは気象庁の正式な震度計・震度観測装置ではありません。**
表示される値は「参考値」であり、公式に発表される震度と一致することを
保証するものではありません。

アルゴリズムの調査経緯・出典・簡略化した点・不確実な点は、必ず
[`ALGORITHM.md`](./ALGORITHM.md) を参照してください。数式・パラメータ・
出典に関する説明はすべてそちらに集約しています。本READMEはアプリと
プロジェクトの使い方に関する説明のみを扱います。

## 何をするアプリなのか

スマートフォンを机などの安定した場所に静置し、内蔵の加速度センサーから
得られる3軸(X/Y/Z)の加速度データをリアルタイムに処理して、
気象庁の「計測震度」フィルタを防災科研方式(功刀・他, 2008)に基づき
時間領域の漸化式(IIR)フィルタで近似した「リアルタイム震度相当値」を
算出・表示します。あわせて生波形・フィルタ後波形・震度の推移を
簡易グラフで表示し、測定データをCSVに保存できます。

## 現在実装されている機能

- 加速度センサーからのリアルタイム取得(後述)
- 防災科研方式(2008年版係数)による6段の双2次(biquad) IIRフィルタでの
  リアルタイム震度相当値の計算(`filter`パッケージ, `processor`パッケージ)
- 3軸合成・気象庁式の丸め処理を含む震度計算
- 静止時のセンサーオフセット・ノイズの常時モニタ表示(シェイク操作不要)
- 生波形/フィルタ後波形/震度推移の簡易折れ線グラフ表示(`WaveformView`)
- 計測データのCSV保存(`CsvRecorder`。列: timestamp, ax, ay, az,
  filteredX, filteredY, filteredZ, combined, realtimeIntensity)
- K-NET/KiK-net ASCII形式の強震波形ファイルを使ったオフライン検証モード
  (`validation`パッケージ, `ValidationActivity`) - 気象庁公式のFFTベース
  アルゴリズムとリアルタイム版の誤差を確認できる
- 震度階級バッジ・計測震度相当・加速度(PGA相当)・震度階級履歴帯・
  XYZ加速度波形を2列(左上=震度階級/右上=震度推移、
  左下=計測震度相当・加速度/右下=XYZ加速度波形)にまとめたコンパクトな
  モニターカード。震度階級バッジと履歴帯は固定10色、計測震度相当・
  加速度は現在値を単色バーで表示(いずれもingen084氏の
  KyoshinShindoColorMapによる色付け、アプリ内クレジット表記あり)
- センサーノイズによる表示のチカチカ対策として、震度階級バッジ・計測震度相当・
  加速度・履歴帯の表示更新を約1Hzに間引く。震度階級側のヒステリシスは採用せず、
  1Hzの表示更新そのものを安定化手段とする。`rawIntensity`は毎サンプル計算・
  CSV記録され続ける(詳細はALGORITHM.mdおよびコード内コメント参照)
- 「加速度に対して計測震度が細かく追従しすぎる」問題への対策は、
  連続値側のピーク保持や震度階級側のヒステリシスを重ねず、表示更新を約1Hzに
  間引く方式に整理した。計測震度相当は加速度と同様、現在サンプルの瞬時値を
  そのまま表示する。

上記のうちCSV保存・オフライン検証モード・震度表示拡張カードは、
コードとしては実装済みですが、実機での動作は本README作成時点では
未確認です(下記「現在確認済みの動作」参照)。

## 使用しているセンサー

- `Sensor.TYPE_ACCELEROMETER` (重力込みの加速度。単位はAndroid標準のm/s²で
  取得し、アプリ内でgal(1 gal = 0.01 m/s²)に変換して処理する)
- サンプリングは `SensorManager.SENSOR_DELAY_FASTEST` を要求する。
  Android 12(API 31)以降でこれを使うには
  `android.permission.HIGH_SAMPLING_RATE_SENSORS` の宣言が必要
  (`AndroidManifest.xml`で宣言済み。実行時ダイアログは出ないnormal権限)。
  端末がこの権限に対応していない、または登録に失敗した場合は
  `SENSOR_DELAY_GAME`(約50Hz相当)に自動的にフォールバックする
  (`AccelerometerSource.kt`)。
- センサーイベントは専用のバックグラウンドスレッド(`HandlerThread`)上で
  処理され、UI表示は約30fpsに間引いてメインスレッドに反映される
  (詳細はコード内コメント参照)。

## リアルタイム震度計算の概要

気象庁の計測震度フィルタ `H(f) = FL(f)・FF(f)・FH(f)` を、防災科研方式
(功刀・他, 2008)に基づき6段の双2次IIRフィルタ+ゲインで近似し、
3軸合成後の現在値を `I = 2*log10(a) + 0.94` に入れて
「リアルタイム震度相当値」を算出しています。表示側は約1Hzで更新することで、
階級のチカチカを抑えています。

このフィルタ係数は、一次資料(論文)そのものをJ-STAGEのrobots.txt制限で
直接取得できなかったため、論文の内容を解説した第三者記事と、それに
付随する検証済みオープンソース実装から数値的に抽出・検算したものです。
現在防災科研が正式に使っている2013年改良版ではなく、2008年版の係数を
使っている点を含め、出典・限界・簡略化点はすべて `ALGORITHM.md` に
詳しく記載しています。現在のリアルタイム版では、追従遅延を避けるため
10秒の評価窓と震度階級側のヒステリシスを採用せず、現在サンプルの瞬時値から
震度相当値を計算し、震度階級の表示だけを約1Hzで更新しています。

## ビルド方法

Gradle Wrapper を同梱しているため、Android Studioでも、
コマンドラインからでもビルドできます。

```bash
git clone <このリポジトリのURL>
cd RealtimeIntensity
./gradlew assembleDebug
```

Windowsの場合は `gradlew.bat assembleDebug` を使用してください。

- `compileSdk = 34` / `minSdk = 26` / AGP `8.5.2` / Kotlin `1.9.24` /
  Gradle Wrapper `8.7` としています(Android Gradle Plugin 8.5系の
  公式な最小必須Gradleバージョンが8.7のため)。
- `applicationId` は `com.example.rtintensity` です。現在実機で正常動作
  している設定のため、公開のためだけに変更していません。配布用に
  変更する場合は各自調整してください。

### 既知のビルド上の注意点(トラブルシューティング)

- **Gradle実行用JDKについて**: 非常に新しいJDK(JDK 25系などプレビュー/
  最新世代)では、このプロジェクトのGradle/AGPバージョンとの組み合わせで
  ビルドに失敗することが実際に確認されています。Android Studioの
  「Settings > Build, Execution, Deployment > Build Tools > Gradle」
  で **Gradle JDKを17系に設定する**ことで解決することを確認済みです。
  コマンドラインから `./gradlew` を使う場合も、`JAVA_HOME` をJDK 17系に
  向けてください。

## 実機での実行方法

1. 上記の手順でビルドするか、Android Studioでプロジェクトを開いて
   実機(USBデバッグ有効化済み)またはエミュレータに実行(Run)する。
2. アプリを起動し、スマートフォンを机など安定した場所に静置する。
3. 「計測開始」ボタンを押す。加速度・フィルタ後波形・リアルタイム震度
   相当値・波形グラフが表示される。
4. 「計測停止」ボタンで測定を終了する。

## 注意事項

- 本アプリは学習・検証目的であり、防災・避難行動の判断材料として
  使用することを意図していません。
- 表示される「リアルタイム震度相当値」は気象庁が発表する正式な震度と
  一致することを保証しません。あくまでスマートフォン内蔵センサーによる
  参考値です。
- フィルタ係数は防災科研方式(功刀・他, 2008年版)を独自に検算・実装した
  ものであり、防災科研の公式実装そのものではありません
  (詳細は`ALGORITHM.md`)。
- 測定はスマートフォンを静止させた状態を前提としています。測定中に
  端末の向きを変えると、重力成分の再配分が地震動と誤検知される
  原因になります。
- 公開されている一次資料(論文)そのものは、本プロジェクトの調査時点で
  J-STAGEのrobots.txt制限により直接確認できていません。より正確な
  実装を目指す場合は、`ALGORITHM.md`記載の文献情報を参照し、実際の
  論文Appendixの数値と照合することを推奨します。

## 学校のChromebook等、リソースが限られた環境での開発について

Android Studioはメモリ・ディスクを多く使うIDEです。開発環境によっては
リソースが厳しい場合の代替案:
- クラウド上の開発環境でコードを編集し、ビルドは別のPCやCIサービスに
  任せる。
- `filter`パッケージと`processor`パッケージはAndroid APIに依存していない
  ため、そのままKotlin/JVMのコンソールプログラムやユニットテストとして
  より軽量な環境で先に検証できます。
